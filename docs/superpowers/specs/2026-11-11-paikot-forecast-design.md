# Paikot Forecast Design

Paikot is a forecast-only dashboard card beside next month's dues. It models linked repayments and card-funded installment dues without creating ledger transactions. For each card, expose the existing credit limit, billing day, and weekend shift; use current outstanding balance as existing utilization. A planned card-funded due is charged after statement close and included in next month's bill. Existing card balances already include booked purchases, so do not subtract existing plan principal twice. For card installment payments, 0% plans restore the full payment; otherwise ask for monthly principal, with an explicit full-principal estimate warning if skipped. Reuse the existing unpaid loan/card payable data and allow manually entered external dues. Keep forecast scenarios in browser storage.

PayDirect scenarios use the user-provided defaults (minimum ₱1,500, maximum ₱200,000, 95% of available credit, up to 10 per month, two per beneficiary, ₱1,000,000 monthly, fee up to 5%). The per-customer fee and percentage cap are editable estimates. PayDirect is ineligible for loan or debt repayment; retain such rows only as hypothetical card-funded forecasts and show the restriction. PayDirect's card charge can happen up to two banking days before the scheduled payee date, so billing placement uses an explicit planned card-charge date. No backend transaction writes, fees/interest forecasts beyond the configured PayDirect fee, or build/test/preview runs.

Approaches considered: browser-only forecast data vs. backend-backed card metadata. Use the existing backend credit-card terms and account balances for limits and statement timing, while saving only user scenario choices in browser storage; this avoids duplicate card-limit inputs while keeping forecasts transaction-free. PayDirect caps are forecast rules, never transaction validation.
